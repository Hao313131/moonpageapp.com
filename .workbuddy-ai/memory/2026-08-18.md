# 2026-08-18

## GSC 索引编制告警排查与修复（moonpageapp.com）

用户贴了 Search Console 三类告警：网页会自动重定向 / 备用网页（有适当的规范标记）/ 未找到(404)。
站点为 Next.js 16 `output:"export"` + `trailingSlash:true`，部署到 GitHub Pages（自定义域名 moonpageapp.com）。

**根因（代码层，已修复）**：trailingSlash 下真实页面在 `/foo/`，canonical/sitemap 也带斜杠，但有两处对外暴露的 URL 用无斜杠写法，Google/Bing 顺着爬会 301 跳转到 `/foo/`，被记为"重定向"+"备用网页"：
1. `scripts/gen-feed.ts` 的 RSS `<link>/<guid>`（story/guide/collection）无斜杠 → 已加斜杠。
2. `lib/site.ts` 的 `hubJsonLd` BreadcrumbList/ItemList URL（`${SITE.domain}${path}`，无斜杠）→ 新增 `withSlash()` 统一补斜杠（注意：裸域名 `https://moonpageapp.com` 也会被 `.com` 误判为扩展名，需用"剥离 host 后再判路径段"的写法）。
3. `app/privacy-choices/page.tsx`、`app/support/page.tsx` 里的 `/privacy` 裸链接 → 改为 `/privacy/`。

**验证**：`npm run build` 后复跑全站扫描（/tmp/seo_check.mjs）→ sitemap 0 缺文件、站内 0 内容 404、0 个会 301 的无斜杠内链；构建产物 JSON-LD 与 feed.xml 均带斜杠。

**未修复（仓库外/外部因素）**：
- 404 来自外部：旧外链死 slug、GitHub Pages 项目地址 `user.github.io/moonpageapp.com`、www 子域（若 DNS 有 www 但 GH Pages 未配置 www）。`_redirects`/`_headers` 已写好但 GH Pages 忽略，需 Cloudflare 反代或迁 Cloudflare Pages/Netlify 才生效。
- 仍需 `git push` 触发 GitHub Pages 部署，再在 GSC 用"网址检查"请求重新编入索引。

**约定**：本仓库 EAS 规则不适用（那是 RN app）；GitHub Pages 静态构建免费、本地 `npm run build` 可作真实验证，但 push=部署由用户决定。
