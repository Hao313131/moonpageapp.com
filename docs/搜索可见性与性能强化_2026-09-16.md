## 1. Google Search Console 验证（最高优先级：验证前所有 CTR 数据都是盲的）

**现状**：代码已接 `NEXT_PUBLIC_GSC_VERIFICATION`，CI（`.github/workflows/deploy-pages.yml`）从 repo Secrets 读。填了 token 就自动输出 `<meta name="google-site-verification">`；没填则**不输出标签**（比填错更安全）。

### 方式 A —— HTML 标签（推荐，约 5 分钟）

1. 打开 <https://search.google.com/search-console> → **Add property** → 选 **URL prefix** → 填 `https://moonpageapp.com`
2. 选 **HTML tag**，复制 `content="..."` 里的那串值（形如 `AbC123...`）
3. GitHub 仓库 → **Settings → Secrets and variables → Actions → New repository secret**
   - Name: `GSC_VERIFICATION` ／ Value: 粘贴上一步的值
4. 同法可加（可选，各站验证独立）：
   | Secret 名 | 平台 | 对应 meta |
   |---|---|---|
   | `BING_VERIFICATION` | Bing Webmaster Tools | `msvalidate.01` |
   | `YANDEX_VERIFICATION` | Yandex Webmaster | `yandex-verification` |
   | `PINTEREST_VERIFICATION` | Pinterest Business | `p:domain_verify` |
5. 触发一次部署（push 到 master，或 Actions → Deploy to GitHub Pages → Run workflow）
6. 回 GSC 点 **Verify**

### 方式 B —— DNS TXT（那样 Secrets 可全空）

在域名 DNS 加一条 TXT：`google-site-verification=<值>`，其余同上。

### 验证后立刻做

- **提交 sitemap**：GSC → Sitemaps → 输入 `sitemap.xml`（现为 **159** 条 URL）
- **拉 striking distance**：`gsc_client --striking` → 拿到排名 4–20 位的查询，这些是「再推一把就进前三」的词，是接下来内容/内链的靶心

## 2. GitHub Pages 开启 Enforce HTTPS

**现状**：`http://moonpageapp.com/` 实测返回 **200，不跳 https**（`www → apex` 的 301 是正常的）。根因是 Pages 的 **Enforce HTTPS 开关没开**。

**前置条件（关键）**：Enforce HTTPS 只有在**自定义域名的 TLS 证书签发完成后**才可勾选。GitHub 自动签证书，前提是 DNS 指向正确：

- apex（`moonpageapp.com`）：A 记录 → `185.199.108.153` / `185.199.109.153` / `185.199.110.153` / `185.199.111.153`（或 ALIAS/ANAME）
- `www`：CNAME → `hao313131.github.io`

**步骤**：

1. 仓库 → **Settings → Pages**
2. 确认 Custom domain 为 `moonpageapp.com`（已配）
3. 等 **DNS check successful** + 证书签发（通常几分钟，最长 24h）
4. 勾选 **Enforce HTTPS**
5. 复验：`curl -I http://moonpageapp.com/` → 应为 `301` 指向 https

## 3. Cloudflare 前置（一次同时解决：缓存 + legacy 301 + https + Brotli/HTTP3）

**为什么必须做**：GitHub Pages **忽略** `public/_headers` 与 `public/_redirects`（实测图片 `cache-control: max-age=600`、legacy slug 仍 404）。前置 Cloudflare 后，这两个文件里的规则用 Cloudflare 的 **Cache Rules / Redirect Rules** 复刻即可生效——这也是**第 ③ 条指令（LCP）最大的剩余杠杆**：Brotli + HTTP/3 + 长缓存直接压低重复访问的 LCP。

### 3.1 DNS

- 在域名注册商处把 **nameserver** 改为 Cloudflare 分配的 NS
- Cloudflare DNS 内：
  - apex `A` → GitHub Pages 的 4 个 IP（**橙云开启**=走代理）
  - `www` `CNAME` → `hao313131.github.io`（橙云）

### 3.2 SSL/TLS

- **SSL/TLS → Overview → 模式选 `Full (strict)`**（GitHub Pages 有有效证书）
- **Edge Certificates**：开启 **Always Use HTTPS**、**Automatic HTTPS Rewrites**、**HTTP/3 (QUIC)**、**Brotli**

### 3.3 缓存规则（复刻 `public/_headers`）

**Caching → Cache Rules**，按下表建（用动作 *Set Cache-Control*）：

| 匹配 | Cache-Control |
|---|---|
| `/covers/*`、`/*.webp`、`/*.png`、`/*.svg`、`/*.woff2` | `public, max-age=86400, stale-while-revalidate=604800` |
| `/_next/static/*`、`/assets/*`、`/*.js`、`/*.css` | `public, max-age=31536000, immutable` |
| `/*.html`、`/sitemap.xml`、`/feed.xml` | `public, max-age=3600` |

### 3.4 重定向规则（复刻 `public/_redirects`）

**Rules → Redirect Rules**：

1. `https://www.moonpageapp.com/*` → `https://moonpageapp.com/$1`，**301**
2. 以下 legacy slug → 就近 hub，**301**：
   - `/stories/milos-little-boat` → `/stories/`
   - `/collections/stories-about-honesty` → `/collections/`
   - `/collections/stories-about-music` → `/collections/`
   - （两个斜杠/无斜杠形式都建）

### 3.5 复验

```bash
curl -I https://moonpageapp.com/covers/wp_b01_1_blue_sea_cover.webp   # → cache-control: max-age=86400
curl -I https://moonpageapp.com/stories/milos-little-boat/            # → 301
curl -I http://moonpageapp.com/                                       # → 301 → https
```

## 4. 站内评价体系（代码已上线；接一个 endpoint 即可收评价）

### 4.1 为什么必须自建，不能搬 App Store 评分

Google 结构化数据政策明文：**"Don't aggregate reviews or ratings from other websites."** 把 App Store 评分搬进自己站的 JSON-LD = 跨站聚合，有手动处罚风险——而本站整条增长策略都押在自然搜索上。**唯一合规路径 = 收集自己的评价。**

### 4.2 已实现的代码

| 文件 | 作用 |
|---|---|
| `data/reviews.json` | 评价存储（**当前为空**） |
| `lib/reviews.ts` | 读取 + 聚合 + 生成 `AggregateRating`/`Review` 节点；**count=0 时不输出任何评分标记** |
| `components/ReviewSection.tsx` | 故事页**可见**评价区（Google 要求：被标记的评分必须页面可见） |
| `components/ReviewForm.tsx` | 提交表单，POST 到 `NEXT_PUBLIC_REVIEWS_ENDPOINT`；未配 endpoint 时**自动降级为 mailto 链接**（不假装收集） |
| `scripts/ingest-reviews.mjs`（`npm run reviews:ingest`） | 把提交合并进 store，去重 + 校验 |
| `app/stories/[slug]/page.tsx` | 故事 `Book` 节点条件输出 `aggregateRating` + `review` |
| `app/layout.tsx` | 首页 `MobileApplication` 节点条件输出**站点总分** |

### 4.3 你要做的一步：接一个 endpoint（任选其一，均免费）

- **Cloudflare Worker**（若已做第 3 步，最顺手）：一个 `POST` 接收 JSON，写 KV 或转发邮件
- **Formspree / Basin / Getform**：表单后端，POST 后邮件通知
- **Google Apps Script Web App**

拿到 URL 后，在 `.github/workflows/deploy-pages.yml` 的 build 步加：

```yaml
          NEXT_PUBLIC_REVIEWS_ENDPOINT: ${{ secrets.REVIEWS_ENDPOINT }}
```

并在 repo **Settings → Secrets** 加 `REVIEWS_ENDPOINT`。

### 4.4 运营流程

1. 用户提交 → endpoint 收件
2. 导出为 `data/reviews-inbox.json`（数组：`{key,rating,author,text,date}`）
3. `npm run reviews:ingest`
4. `git add data/reviews.json` → commit → push（触发部署）
5. 上线后：故事页显示星级 + 可见评价 + `Book.aggregateRating`；首页 App 节点显示站点总分

### 4.5 已端到端验证（随后已完全回滚）

用 2 条**临时**评价跑通全链路，确认：

- 故事页 `Book.aggregateRating` = `{"ratingValue":"5.0","reviewCount":1}` + 1 个 `Review` 节点 + 页面可见 `5.0 out of 5`
- 首页 `MobileApplication.aggregateRating` = `{"ratingValue":"4.0","reviewCount":1}`
- **随后完全回滚**：`grep -rl aggregateRating out/` = **0**，线上不含任何测试评价
