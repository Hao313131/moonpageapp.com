## 三、我做不到的（必须用你的账号）

### 3.1 GSC 验证 —— 需要你的 Google 账号

**为什么我做不到**：验证的本质是「证明你拥有这个域名」。
三种方式（meta 标签 / DNS TXT / HTML 文件）**都需要你 Google Search Console 账号里生成的专属 token，或你域名 DNS 的控制权**。
我手上没有你的 Google 凭据，也没有域名注册商的凭据 —— 这不是技术问题，是权限问题。

**你要做（约 5 分钟）**：

| 步骤 | 操作 |
|---|---|
| 1 | 打开 `search.google.com/search-console` → Add property → URL prefix → 填 `https://moonpageapp.com` |
| 2 | 选 **HTML tag**，复制 `content="..."` 里的值 |
| 3 | GitHub 仓库 → Settings → Secrets and variables → Actions → New secret：<br>Name `GSC_VERIFICATION`，Value 粘贴上一步的值 |
| 4 | 触发一次部署（push 到 master，或 Actions → Run workflow） |
| 5 | 回 GSC 点 **Verify** |

可选：同法加 `BING_VERIFICATION` / `YANDEX_VERIFICATION` / `PINTEREST_VERIFICATION`。
验证后立刻：提交 `sitemap.xml` + 跑 `gsc_client --striking` 拿排名 4–20 的词。

### 3.2 Cloudflare 前置 —— 需要你的 Cloudflare 账号 + 域名 NS

**为什么我做不到**：需要你的 Cloudflare 账号（我没有 CF API token），
且**必须到域名注册商处把 nameserver 改成 Cloudflare 分配的 NS** —— 这一步只有域名所有者能做。

**为什么值得做**：一次同时解决四件事 —— 缓存头（GitHub Pages 无视 `_headers`）、legacy slug 301、https 强制、Brotli + HTTP/3。
这也是 LCP 剩余最大的杠杆。

**你要做**：

| 步骤 | 操作 |
|---|---|
| 1 | 注册 Cloudflare → 添加站点 `moonpageapp.com` |
| 2 | 到注册商处把 NS 改为 Cloudflare 分配的地址 |
| 3 | DNS：apex A → GitHub 的 4 个 IP（橙云）；<br>`www` CNAME → `hao313131.github.io`（橙云） |
| 4 | SSL/TLS → 模式 **Full (strict)**；<br>开 Always Use HTTPS、HTTP/3、Brotli |
| 5 | Caching → Cache Rules：复刻 `public/_headers` 的 3 组规则 |
| 6 | Rules → Redirect Rules：复刻 `public/_redirects` 的 www 与 legacy slug 301 |

完整规则表（含每条匹配与 `Cache-Control` 值）见仓库内同主题文档。

### 3.3 评价 endpoint —— 可选升级（不接也能用）

**现状**：表单在未配 endpoint 时**自动降级为 mailto 链接**，评价仍可收集（走邮件），
再用 `npm run reviews:ingest` 入库 —— **所以评价体系现在就是可用的**，只是收集环节手动。

**要自动化**：接一个 endpoint（Cloudflare Worker / Formspree / Apps Script 均可），
在 CI build 步加 `NEXT_PUBLIC_REVIEWS_ENDPOINT` 并写入 repo Secrets。
