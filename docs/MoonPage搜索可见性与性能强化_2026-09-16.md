## 三、剩下的：需要你账号的部分

### 3.1 GSC 验证 —— 已完成（原计划的 meta 标签路线作废）

**2026-09-16 你在 Search Console 里看到「您是经过验证的所有者」→ 资源已验证。**

**所以下面这条路不用走了**：`GSC_VERIFICATION` secret → `NEXT_PUBLIC_GSC_VERIFICATION` → `<meta name="google-site-verification">`。
我实测过线上首页，**一个搜索引擎验证标签都没有**（`google-site-verification` / `msvalidate.01` / `yandex-verification` / `p:domain_verify` 全为 0），
说明你的所有权是用**不落在 HTML 里**的方式验的（DNS TXT / HTML 文件 / Google Analytics / Tag Manager 之一）—— 这比 meta 标签**更好**：零代码改动、零 secret、不用重新部署。

> **注意**：验证方式只影响「怎么证明是你的」，**不影响能看到多少数据**。只要资源已验证，效果报告就是全的。

**现在真正要做的（GSC 侧，约 2 分钟）**：

| 步骤 | 操作 | 为什么 |
|---|---|---|
| 1 | 左侧 **站点地图** → 添加新的站点地图 → 填 `sitemap.xml` → 提交 | 站内 159 条 URL 主动交给 Google，不等它自己爬 |
| 2 | 顶部 **网址检查** → 填 `https://moonpageapp.com/` → **请求编入索引** | 推首页入队 |
| 3 | 同法对 4 个核心页各做一次：<br>`/bedtime-stories`、`/toddler-bedtime-stories`、`/cozy-bedtime-stories`、<br>`/winter-bedtime-stories` | 让新 hub 尽快进索引 |
| 4 | **等 2–3 天**，再看 **效果 → 查询** | 数据要攒，当天看是空的 |

**可选**：同法把 Bing 也接上（`bing.com/webmasters`，导入 GSC 资源即可），
加上仓库已有的 IndexNow 自动 ping，Bing/Yandex 侧基本零维护。

### 3.2 Cloudflare 前置 —— 需要你的 Cloudflare 账号 + 域名 NS

**为什么我做不到**：需要你的 Cloudflare 账号（我没有 CF API token），
且**必须到域名注册商处把 nameserver 改成 Cloudflare 分配的 NS** —— 这一步只有域名所有者能做。

**为什么值得做**：一次同时解决四件事 —— 缓存头（GitHub Pages 无视 `_headers`）、legacy slug 301、https 强制、Brotli + HTTP/3。
这也是 LCP 剩余最大的杠杆。

**你要做**：

| 步骤 | 操作 |
|---|---|
| 1 | 注册 Cloudflare → 添加站点 `moonpageapp.com` |
| 2 | 到注册商处把 NS 改为 Cloudflare 分配的地址 |
| 3 | DNS：apex A → GitHub 的 4 个 IP（橙云）；<br>`www` CNAME → `hao313131.github.io`（橙云） |
| 4 | SSL/TLS → 模式 **Full (strict)**；<br>开 Always Use HTTPS、HTTP/3、Brotli |
| 5 | Caching → Cache Rules：复刻 `public/_headers` 的 3 组规则 |
| 6 | Rules → Redirect Rules：复刻 `public/_redirects` 的 www 与 legacy slug 301 |

规则来源就是仓库里的两个文件（Cloudflare 规则照它们复刻即可）：
`public/_headers`（缓存头）、`public/_redirects`（www 与 legacy slug 的 301）。
这两个文件在 GitHub Pages 上**完全无效**（实测图片缓存 `max-age=600`、legacy slug 404），
所以内容本身是对的，只是需要一个能读它们的 CDN 前置。

### 3.3 评价 endpoint —— 可选升级（不接也能用）

**现状**：表单在未配 endpoint 时**自动降级为 mailto 链接**，评价仍可收集（走邮件），
再用 `npm run reviews:ingest` 入库 —— **所以评价体系现在就是可用的**，只是收集环节手动。
